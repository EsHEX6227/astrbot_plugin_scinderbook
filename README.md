# astrbot_plugin_kwbook · 关键词词条本

把「检索词」和「正文」拆开的两段式词条注入插件：**用关键词命中，只把正文注入上下文。**

- 不调用任何 embedding、不发一次网络请求，索引和召回全在本地
- 检索词只用来匹配，永远不会出现在模型看到的上下文里
- 一个词条一个 `.md`，格式就是「标题 + 一行检索词 + 正文」
- 命中才注入，没命中就安静地什么都不做

---

## 为什么会有这个插件

很多人维护知识库时是这样写的：

```md
# Kn视力

看 观看 视觉 视力 看见 视
作为大语言模型的电子猫娘，你默认没有视觉能力。
```

第一行是给人看的检索词，下面是给模型看的正文。但原生向量知识库会把整段一起做 embedding：检索词稀释了语义，「看 观看 视觉 视力 看见 视」这种词表又会被向量当成正文的一部分，召回精度反而变差。

KWBook 的做法是**把两件事分开**：

```
关键词索引（本地 FTS5 + jieba）  ← 只有检索词和正文参与匹配
        │  命中
        ▼
注入上下文                      ← 只有「条目名 + 正文」
```

代价是它没有语义泛化能力（见「已知限制」），换来的是精确、便宜、可解释。

## 词条格式

### 极简格式（推荐）

```md
# Kn视力

看 观看 视觉 视力 看见 视
作为大语言模型的电子猫娘，你默认没有视觉能力。
当且仅当有具体通知或者你能调用视觉工具时，你可以使用「我看见……」这类表达。
```

- 一级标题 `# xxx` 是条目名
- 标题下、正文前的**第一行**是检索词，空格分隔
- 其余全部是正文

### YAML frontmatter（要常驻或正文开头很特殊时）

```md
---
keywords: [署名, 落款, 签名]
always: true
---

# Kn署名

落款写 YuJie.ctr，位置在正文末尾。
```

`always: true` 的词条无论是否命中都会注入，适合放全局基调。

## 安装

```bash
cd AstrBot/data/plugins
git clone https://github.com/<你的仓库>/astrbot_plugin_kwbook
```

重启 AstrBot，在「插件」页启用，然后在插件配置里填 `vault_dir`（词条目录，会递归扫描 `.md`）。

依赖：`jieba`（可选）。装了按词切分，没装自动退化成「中文二元组」切分——能用，但召回会差一些。

---

## 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `vault_dir` | 空 | 词条目录，必填 |
| `keyword_mode` | `auto` | `auto`：优先 frontmatter，否则把标题后第一行当检索词；`frontmatter_only`：只认 frontmatter |
| `top_n` | `3` | 每轮最多注入几个词条 |
| `max_chars` | `1500` | 单轮注入的总字数上限，超出按得分从高到低截断 |
| `min_score` | `0.0` | 命中分数下限，0 表示只要有检索词命中就注入 |
| `inject_position` | `user_tail` | `user_tail`：附在本轮对话尾部（推荐，不破坏 KV 前缀缓存）；`system_prompt`：拼进系统提示词（会打断前缀缓存） |
| `always_files` | `[]` | 常驻词条文件名，例如 `["Kn郁洁背景.md"]` |
| `rebuild_interval_min` | `0` | 自动重建索引的间隔（分钟），0 = 只在启动和 `/kwb reload` 时重建 |
| `debug` | `false` | 打印命中详情 |

---

## 指令

| 指令 | 作用 |
|---|---|
| `/kwb` | 看索引统计 |
| `/kwb reload` | 重建索引 |
| `/kwb test <关键词>` | 手工试一次召回，看命中哪些条目和分数 |

## 实测

同一批词条（27 条 Kn 词条，6923 字正文），三种召回方式的对比：

| 查询 | nomic-embed-text | bge-m3 | KWBook |
|---|---|---|---|
| 你能看见吗 | ❌ Kn触觉 0.737 | — | ✅ **Kn视力** 6.83 |
| 消息抖动是什么 | ❌ Kn触觉 0.754 | ✅ Kn消息抖动 | ✅ **Kn消息抖动** 8.31 |
| 署名应该怎么落款 | ✅ Kn署名 | ✅ Kn署名 | ✅ **Kn署名** 10.87 |
| 我没有触觉吗 | ✅ Kn触觉 0.671（第二名 0.650） | ✅ Kn触觉 0.704（第二名 0.517） | ✅ **Kn触觉** 4.34 |
| 京海市在哪（库里没有） | 硬凑一条 | 硬凑一条 | ✅ **无命中** |

要点是最后一行：向量检索在「库里没有」时也会硬凑 top-k，KWBook 会明确不注入。

索引构建耗时 0.69 秒（27 条 / 7 KB），单次召回毫秒级，token 成本只有注入的正文本身。

## 已知限制

- **没有语义泛化**：查「视力」不会命中只写了「眼睛」的条目。要么把同义词写进检索词行，要么另外维护条目。这是它便宜和精确的代价。
- **中文分词依赖 jieba**：没装时退化成一个字/二元组，召回质量下降但不会崩。
- **需要 FTS5**：极少数自行编译的 Python 没带 FTS5，会直接报错。用官方发行版一般都有。
- **不做增量**：`/kwb reload` 是全量重建，几 KB 到几 MB 的词条目录都在一秒内。
